# 코드 설명서 전체 색인

## 1. 문서 목적

이 폴더는 협동 로봇 매뉴얼 기반 오프라인 멀티모달 RAG 시스템의 핵심 Python 코드를 초심자도 따라갈 수 있도록 설명한다. 단순히 함수 이름만 나열하지 않고, 각 파일이 전체 파이프라인에서 맡는 역할과 입력·출력 데이터, 함수 내부 처리 순서, 다른 파일과의 호출 관계를 함께 정리한다.

평가용 실험 스크립트와 논문 DOCX 생성 스크립트는 시스템 실행의 핵심 경로와 분리되므로 이번 설명 범위에서 제외하였다.


## 4. 실행 명령

### 4.1 SigLIP 모델 준비

최초 한 번 또는 `models/siglip_local`이 없을 때 실행한다.

```powershell
.\.venv\Scripts\python.exe scripts\download_siglip.py
```

### 4.2 전처리와 DB 구축

```powershell
.\.venv\Scripts\python.exe src\unified_extractor.py
.\.venv\Scripts\python.exe src\text_filter.py
.\.venv\Scripts\python.exe src\embedding_text_image.py
```

`unified_extractor.py`와 `text_filter.py`는 동일한 PDF를 서로 다른 방식으로 처리한다. 두 파일은 서로 직접 호출하지 않지만, `embedding_text_image.py`가 양쪽 결과를 모두 필요로 하므로 둘 다 먼저 완료해야 한다.

### 4.3 앱 실행

먼저 Ollama 서버와 필요한 로컬 모델이 준비되어 있어야 한다.

```powershell
powershell -ExecutionPolicy Bypass -File .\start_ollama.ps1
.\.venv\Scripts\python.exe -m streamlit run src\app_qwen.py
```

Gemma 또는 Llama를 사용할 때는 마지막 파일만 각각 `app_gemma.py`, `app_llama.py`로 바꾼다.

## 6. G3와 G4의 차이

- G3는 질문과 가까운 텍스트, 텍스트에 연결된 이미지, 주변 페이지 이미지, 이미지 전용 검색 결과를 합쳐 이미지 후보를 정렬한다.
- G4는 G3의 후보 생성 구조를 유지하면서 질문에서 실습 단계를 추정한다.
- 단계 분류 점수와 1·2위 점수 차이가 기준을 통과할 때만 단계별 페이지·키워드·섹션 점수를 추가한다.
- 분류 신뢰도가 낮으면 `stage_label=None`이 되어 G3 결과로 되돌아간다.

## 7. BBox와 SigLIP의 역할

- 이미지 추출 단계의 BBox는 이미지와 텍스트가 PDF 어디에 있었는지 기록한다.
- DB 구축 단계의 BBox 거리는 관련 가능성이 있는 공간 후보를 제한하는 데 사용한다.
- 최종 텍스트-이미지 매핑 순서는 SigLIP 이미지·텍스트 feature의 cosine 유사도로 결정한다.
- 따라서 BBox는 후보 경계이고 SigLIP은 후보 내부의 의미 순위 신호이다.

## 8. 재실행 시 주의사항

1. `embedding_text_image.py`는 기존 텍스트 컬렉션과 이미지 컬렉션을 삭제한 뒤 다시 구축한다.
2. DB 구축 중 중단되면 컬렉션이 일부만 저장될 수 있으므로 처음부터 다시 실행하는 편이 안전하다.
3. 전처리 기준이나 원본 PDF를 변경하면 이미지, 텍스트, 매핑, DB를 순서대로 다시 생성해야 한다.
4. `unified_extractor.py`는 출력 폴더의 기존 이미지 전체를 먼저 비우지 않는다. 과거 실행의 파일이 남더라도 최신 JSON에 없는 이미지는 정상 파이프라인에서 참조되지 않지만, 폴더 자체는 불필요한 파일을 포함할 수 있다.
5. 앱 실행 중에는 SigLIP을 다시 계산하지 않는다. 앱은 전처리에서 저장된 매핑 정보와 벡터 DB를 사용한다.
6. `ExactVectorCollection`은 정확한 순위를 위해 컬렉션 임베딩 전체를 RAM에 올려 전수 비교한다. 데이터가 크게 늘면 메모리 사용량과 검색 시간이 함께 증가한다.
