# `src/unified_extractor.py` 상세 설명서

## 1. 파일 역할

`unified_extractor.py`는 원본 PDF에서 이미지를 꺼내고, 큰 이미지를 가능한 도면 단위로 나누고, 명백한 빈 이미지·반복 로고·작은 아이콘을 제거한 다음, SigLIP으로 기술 도면 가능성을 판별한다.

최종 결과는 이미지 파일과 이미지 메타데이터 JSON으로 저장된다.

## 2. 입력과 출력

### 입력

- `data/raw/A-Series.pdf`
- `models/siglip_local/`

### 출력

- `data/processed/final_refined_data/`: 선별된 이미지 파일
- `data/processed/final_processing_report.json`: 파일명, 페이지, BBox, SigLIP 도면 점수

### 출력 메타데이터 예시

```json
{
  "file_name": "page_12_img_3_0.png",
  "page": 12,
  "bbox": {"x0": 80.2, "y0": 220.1, "x1": 510.4, "y1": 610.8},
  "siglip_score": 0.8732
}
```

## 3. 주요 상수

| 상수 | 값 | 의미 |
|---|---:|---|
| `DEVICE` | CUDA 가능 시 `cuda`, 아니면 `cpu` | SigLIP 실행 장치 |
| `MIN_SIZE` | 120 | 작은 이미지 판정 기준 |
| `ICON_ASPECT_RATIO_TOLERANCE` | 0.1 | 정사각형 비율 허용 오차 |
| `LOGO_FREQUENCY_THRESHOLD` | 0.1 | 전체 페이지의 10%를 초과해 반복되면 로고 후보 |
| `MIN_SLICE_HEIGHT` | 50 | 분할 이미지의 최소 픽셀 높이 |

모듈을 import하는 순간 `OUTPUT_DIR.mkdir()`가 실행되어 이미지 출력 폴더가 생성된다.

## 4. 함수 설명

### 4.1 `get_image_hash(image_bytes)`

#### 목적

이미지 원본 바이트의 MD5 해시를 계산해 동일한 이미지가 PDF 전체에서 몇 번 등장했는지 세기 위한 키를 만든다.

#### 입력과 반환

- 입력: 이미지 파일의 바이트 데이터
- 반환: 32자리 MD5 문자열

이 해시는 보안 목적으로 사용되지 않고 중복 이미지 식별용으로만 사용된다. 같은 시각 내용이라도 인코딩이 달라 바이트가 다르면 다른 해시가 된다.

### 4.2 `is_blank_or_solid_image(image_bytes)`

#### 목적

완전 투명 이미지, 거의 흰색 또는 검은색인 이미지, 명암 변화가 거의 없는 단색 이미지를 제거한다.

#### 처리 순서

1. 바이트를 PIL 이미지로 연다.
2. 알파 채널이 있는 이미지의 알파 최솟값과 최댓값이 모두 0이면 완전 투명으로 판정한다.
3. 너비와 높이가 10픽셀보다 크면 가장자리 5픽셀을 잘라 테두리 영향을 줄인다.
4. 그레이스케일로 바꾼다.
5. 평균 밝기가 250보다 크거나 5보다 작으면 빈 이미지로 판정한다.
6. 밝기 표준편차가 5보다 작으면 단색 이미지로 판정한다.

#### 반환

- 제거 대상이면 `True`
- 유지 대상이면 `False`
- 이미지 열기나 통계 계산 중 오류가 나면 `False`

오류를 유지 대상으로 처리하므로 손상 이미지가 다음 단계까지 전달될 수 있다.

### 4.3 `split_image_by_text_walls(page, image_bytes, img_bbox, ext)`

#### 목적

PDF에 여러 도면이 하나의 큰 이미지 객체로 들어 있는 경우, 이미지 내부를 가로지르는 텍스트 영역을 절취선처럼 사용하여 세로 방향으로 나눈다.

#### 입력

- `page`: PyMuPDF 페이지 객체
- `image_bytes`: 원본 이미지 바이트
- `img_bbox`: PDF 페이지 위 이미지 좌표 `[x0, y0, x1, y1]`
- `ext`: 원본 확장자

#### 반환

이미지 조각 딕셔너리의 리스트이다. 각 조각은 `bytes`, `bbox`, `ext`, `width`, `height`를 가진다.

#### 세부 처리

1. 이미지를 RGB PIL 객체로 변환한다.
2. PDF 좌표 높이와 실제 이미지 픽셀 높이의 비율 `scale_y`를 계산한다.
3. 페이지의 텍스트 block을 가져온다.
4. 이미지의 가로 범위와 겹치고, 이미지의 위·아래 경계에서 5포인트 이상 떨어진 텍스트 block을 `cut_zones`에 넣는다.
5. 서로 5포인트 이내에 붙은 텍스트 영역을 하나로 합친다.
6. 이미지 시작점부터 첫 텍스트 위까지, 각 텍스트 사이, 마지막 텍스트 아래를 이미지 조각 후보로 만든다.
7. 조각 높이가 `MIN_SLICE_HEIGHT` 이상일 때만 PNG로 저장할 바이트를 만든다.
8. 각 조각의 BBox를 PDF 좌표 기준으로 다시 기록한다.

#### 폴백

- 이미지 디코딩 실패: 원본 바이트와 BBox를 그대로 반환하고 크기는 0으로 기록한다.
- PDF 이미지 높이가 0 이하: 원본 이미지를 분할하지 않는다.
- 내부 텍스트 영역이 없음: 원본 이미지를 분할하지 않는다.

### 4.4 `run_unified_pipeline()`

#### 목적

PDF 전체 이미지 전처리 과정을 지휘하는 메인 함수이다.

#### 1단계: 모델과 PDF 준비

1. PyMuPDF로 PDF를 연다.
2. 로컬 SigLIP processor와 model을 불러온다.
3. CUDA가 있으면 모델을 GPU로 이동한다.
4. 다음 두 텍스트 후보를 정의한다.
   - 빈 흰 페이지 또는 빈 배경
   - 기술 로봇 도면 또는 공학 schematic

#### 2단계: PDF 이미지 추출과 분할

각 페이지마다 다음을 반복한다.

1. `page.get_images(full=True)`로 이미지 객체 목록을 얻는다.
2. 각 이미지의 `xref`로 실제 바이트를 추출한다.
3. `page.get_image_rects(xref)`로 페이지 위 BBox를 찾는다.
4. `split_image_by_text_walls()`로 필요한 경우 조각낸다.
5. 조각마다 해시와 크기를 묶은 키를 만든다.
6. 같은 키의 전체 등장 횟수를 `occurrence_map`에 누적한다.
7. 페이지, 이미지 번호, 바이트, 크기, BBox를 메모리에 보관한다.

이 단계에서는 모든 이미지 바이트를 `raw_extracted_images`에 저장하므로 PDF 이미지가 매우 많으면 메모리 사용량이 증가한다.

#### 3단계: 하드 필터

각 이미지 조각에 다음 필터를 순서대로 적용한다.

1. `is_blank_or_solid_image()`가 `True`이면 제거한다.
2. 등장 횟수 ÷ 전체 페이지 수가 0.1보다 크면 반복 로고로 보고 제거한다.
3. 너비 또는 높이가 120보다 작으면서 가로세로 비율이 1.0에 가까우면 작은 아이콘으로 보고 제거한다.

하드 필터 통과·실패 수는 `stats`에 누적된다.

#### 4단계: SigLIP 도면 판별

1. 이미지를 RGB로 변환한다.
2. 한 이미지와 두 후보 문장을 processor에 함께 넣는다.
3. `outputs.logits_per_image`를 얻는다.
4. 두 후보 사이에 `softmax(dim=1)`를 적용한다.
5. 두 번째 후보인 기술 도면 확률이 0.5를 초과하면 저장한다.

여기서 사용하는 값은 두 설명 중 어느 쪽이 더 적합한지 비교한 확률이다. `embedding_text_image.py`에서 개별 텍스트-이미지 쌍에 sigmoid를 적용해 기록하는 방식과 목적이 다르다.

#### 5단계: 파일과 보고서 저장

통과 이미지는 다음 규칙으로 저장한다.

```text
page_{페이지}_img_{PDF 이미지 순번}_{조각 순번}.{확장자}
```

JSON에는 파일명, 1부터 시작하는 페이지 번호, BBox, 반올림한 도면 확률을 기록한다.

## 5. 메인 실행부

```python
if __name__ == "__main__":
    run_unified_pipeline()
```

파일을 직접 실행할 때만 전체 파이프라인이 시작된다. 다른 파일에서 import하면 출력 폴더 생성과 상수 정의만 수행되고 파이프라인은 자동 실행되지 않는다.

## 6. 필터 통계

`stats`는 다음 항목을 센다.

- `hard_blank`: 빈 이미지 또는 단색 이미지
- `hard_logo`: 반복 출현 이미지
- `hard_icon`: 작고 정사각형에 가까운 이미지
- `siglip_rejected`: 하드 필터는 통과했지만 도면 확률이 낮은 이미지
- `saved`: 최종 저장 이미지

현재 마지막 출력은 `saved`만 보여주며 전체 통계 딕셔너리를 별도 파일로 저장하지 않는다.

## 7. 재실행 시 주의사항

1. 출력 폴더를 먼저 비우지 않으므로 과거 이미지 파일이 남을 수 있다.
2. 최신 `final_processing_report.json`에는 이번 실행에서 통과한 이미지만 기록된다.
3. 로컬 SigLIP 폴더가 없으면 모델 로딩에서 실패한다.
4. `LOGO_FREQUENCY_THRESHOLD`는 `>` 조건이므로 정확히 10% 등장한 이미지는 제거되지 않는다.
5. 작은 이미지도 정사각형이 아니면 아이콘 필터를 통과한다.
6. 이미지 디코딩 실패 시 크기 0이 반환될 수 있으므로 이후 가로세로 비율 계산에서 예외가 발생할 가능성이 있다.
