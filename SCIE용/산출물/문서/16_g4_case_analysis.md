# G4 개선 및 실패 사례 분석

## 목적

이 문서는 G3 멀티모달 RAG와 G4 상황 인지형 멀티모달 RAG의 차이를 사례 중심으로 설명하기 위한 보고용 정리이다.

본 문서에서 G4는 사용자가 정답 실습 단계를 직접 입력하는 방식이 아니라, 질문에서 실습 단계를 추정한 뒤 단계별 page/section/keyword context map을 이용해 검색 후보를 재순위화하는 방식이다.

정량 결과만으로는 G4가 왜 좋아졌는지 설명하기 어렵기 때문에, G3 대비 정답 이미지 순위가 개선된 사례 3개와 G4에서도 실패한 사례 3개를 선정하였다.

사례 분석을 포함하는 이유는 두 가지이다. 첫째, 개선 사례는 G4가 단순히 점수만 조정한 것이 아니라 질문에서 추정한 실습 단계, page 범위, section heading, keyword context를 이용해 실제로 관련 이미지 후보의 순위를 끌어올렸다는 작동 원리를 보여준다. 둘째, 실패 사례는 G4가 아직 image-level distinction까지 해결하지 못하며, 같은 page 안의 유사 이미지나 단계 추정 오류에 취약하다는 한계를 보여준다. 따라서 개선 사례와 실패 사례를 함께 제시하면, G4의 기여를 과장하지 않으면서도 왜 context-aware re-ranking이 필요한지 설명할 수 있다.

주의: 아래 사례 분석에서는 평가를 위해 정답 이미지 파일명을 확인하지만, G4 단계 분류와 re-ranking에는 정답 이미지 파일명을 사용하지 않았다. G4는 실습 단계명, page 범위, section heading, keyword만 사용한다.

## 전체 결과 요약

| 비교군 | Text R@1 | Text R@5 | Text R@10 | Text MRR | Image R@1 | Image R@5 | Image R@10 | Image MRR | Both@5 | Both@10 |
|---|---:|---:|---:|---:|---:|---:|---:|---:|---:|---:|
| G3 멀티모달 RAG | 81.4% | 95.7% | 100.0% | 0.879 | 32.9% | 70.0% | 75.7% | 0.485 | 70.0% | 75.7% |
| G4 상황 인지형 멀티모달 RAG | 85.7% | 95.7% | 100.0% | 0.903 | 37.1% | 75.7% | 87.1% | 0.539 | 75.7% | 87.1% |

G4는 G3 대비 Image Recall@5를 70.0%에서 75.7%로, Image Recall@10을 75.7%에서 87.1%로, Image MRR을 0.485에서 0.539로 개선하였다. 다만 Image Recall@1은 37.1%로 여전히 낮기 때문에, G4의 성과는 이미지 검색 문제의 해결이 아니라 관련 이미지 후보의 순위 개선으로 해석한다.

## 사례 선정 기준

사례는 전체 성능을 대표하는 통계 지표가 아니라, 정량 결과를 해석하기 위한 질적 분석 자료이다. 개선 사례는 G4가 실제로 어떤 조건에서 순위 개선을 만드는지 설명하기 위한 것이고, 실패 사례는 향후 image caption, bbox 주변 텍스트, 이미지 순서 정보, 세부 단계 라벨이 왜 필요한지 설명하기 위한 것이다.

### 개선 사례

다음 조건을 우선하였다.

- G3에서 정답 이미지가 Top-10 밖이었지만 G4에서 Top-5 안으로 들어온 경우
- 또는 G3에서 하위권이었지만 G4에서 Top-1 또는 Top-2로 상승한 경우
- 질문 기반 단계 추정이 올바르게 수행되어 context-aware re-ranking 효과를 설명할 수 있는 경우

### 실패 사례

다음 조건을 우선하였다.

- G4에서도 정답 이미지가 Top-10 안에 들어오지 못한 경우
- 질문 기반 단계 추정은 맞았지만 세부 이미지 선택에 실패한 경우
- 질문 기반 단계 추정이 애매하거나 오분류되어 G4 효과가 제한된 경우

### 사례 1. 티치 펜던트/USB 데이터 관리

| 항목 | 내용 |
|---|---|
| 질문 번호 | Q31 |
| 질문 | 티치 펜던트에 위치한 USB 포트의 주된 용도는 무엇입니까? |
| 정답 실습 단계 | 티치 펜던트/USB 데이터 관리 |
| 예측 단계 | 티치 펜던트/USB 데이터 관리 |
| 정답 이미지 | `page_103_img_0_0.jpeg` |
| G3 이미지 순위 | Top-10 밖 |

| 판정 | 개선 |

G3에서는 정답 이미지가 Top-10 안에 포함되지 못했다. G4에서는 질문이 `티치 펜던트/USB 데이터 관리` 단계로 추정되었고, USB port, pendant, data import/export와 같은 단계 context가 반영되면서 정답 이미지가 3위까지 상승하였다.

이 사례는 질문 기반 단계 추정이 정확할 때 page/section context가 이미지 후보 재순위화에 직접적으로 기여할 수 있음을 보여준다.

이 사례는 텍스트 질의만으로는 여러 UI 화면이 혼재될 수 있지만, 실습 단계 context를 추가하면 관련 화면 후보를 더 안정적으로 끌어올릴 수 있음을 보여준다.

이 사례는 질문 기반 단계 추정이 오답 후보로 치우쳤지만, 기준 점수와 margin 조건을 통과하지 못해 G4 적용이 보류된 경우이다. 그 결과 검색은 G3 fallback으로 처리되었고, 정답 이미지는 Top-10 안에 포함되지 못했다. `시스템 관리/로그`와 `UI/시스템 정보 확인`은 모두 시스템 화면 관련 표현을 공유하기 때문에 단계 추정기가 두 단계를 혼동하였다.

이 사례는 G4의 성능이 단계 추정 정확도에 영향을 받는다는 점을 보여준다. 따라서 향후에는 단계 profile을 더 세분화하거나, Top-3 후보를 이용한 보조 reranking을 추가하는 방식으로 개선할 수 있다.

## 종합 해석

G4의 장점은 관련 이미지 후보의 순위를 조정할 수 있다는 점이다. G3가 질문 의미와 이미지 후보의 근접도만으로 후보를 정렬하는 데 비해, G4는 질문에서 실습 단계를 추정하고 해당 단계의 page/section/keyword context를 반영하여 일부 정답 이미지 후보를 더 상위로 올릴 수 있었다. Q31, Q23, Q02 사례에서 이 효과가 확인되었다.

반면 G4의 한계도 분명하다. 현재 G4는 page-level 또는 section-level context를 잘 반영하지만, 같은 page 안에 여러 이미지가 있거나 같은 section 안에 유사한 설정 화면이 많은 경우 image-level distinction이 부족하다. 또한 질문 기반 단계 추정이 틀리거나 애매할 경우 G4의 효과가 제한된다.

따라서 현재 결과는 다음과 같이 정리할 수 있다.

- G4는 실제 앱 조건인 단계 추정 기반에서도 G3 대비 이미지 후보의 Top-5/Top-10 포함률과 평균 순위를 개선하였다.
- 그러나 Image Recall@1은 37.1%로 낮아, 정답 이미지를 항상 최상위로 찾는 수준은 아니다.
- 특히 Image Recall@5, Image Recall@10, Image MRR이 모두 상승하였다.
- 다만 세부 이미지 선택 정확도를 높이기 위해서는 이미지 내부 caption, bbox 주변 텍스트, 절차 번호, 하위 실습 단계 분류를 추가로 반영해야 한다.

## 보고용 핵심 문장

G4는 질문에서 실습 단계를 추정하고, 단계별 page/section/keyword context map을 이용해 이미지 후보를 재순위화함으로써 G3 대비 Image Recall@5를 70.0%에서 75.7%로, Image Recall@10을 75.7%에서 87.1%로, Image MRR을 0.485에서 0.539로 개선하였다. 다만 Image Recall@1은 37.1%로 여전히 낮고, 질문 기반 단계 추정 오차와 같은 page 내 유사 이미지 구분 문제도 남아 있다. 따라서 G4는 이미지 검색을 완전히 해결한 방식이 아니라 관련 이미지 후보의 순위를 개선한 방식으로 해석하는 것이 적절하다.
